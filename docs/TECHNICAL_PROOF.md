# Technical Proof

This page is the fast path for engineers and recruiters who want evidence rather than project mythology.

## Canonicalization proof

A public proof slice normalized:

- **3,353 source files**
- **17,766,662 canonical rows**

The important engineering point is not the row count by itself. It is that heterogeneous input was converted into a governed representation that could be validated downstream.

## Repair discipline

HYDRA uses a bounded defect loop:

`TEST -> NAME DEFECT -> MINIMUM REPAIR -> RERUN -> FREEZE`

This keeps repairs attributable and discourages "while I am here" architecture changes that make validation harder to interpret.

## Contract and seam validation

HYDRA tests the handoffs between pipeline stages, including:

- source manifests;
- normalized evidence records;
- schema requirements;
- lineage/provenance;
- downstream admissibility;
- authority ownership.

The goal is to catch a class of failure that ordinary happy-path tests miss: a pipeline that returns PASS only because the test quietly supplied information the upstream component never produced.

## Fail-closed authority behavior

A required downstream field is not considered valid simply because it can be guessed or reconstructed.

If no authoritative native contract owns the value, the pipeline can return an explicit blocker such as:

`BLOCKED_BY_MISSING_AUTHORITY`

That is intentional. It protects the meaning of PASS.

## Real vs synthetic

Public proof must identify whether evidence is:

- real observed data;
- derived from real observed data;
- synthetic;
- shadow-only;
- fixture-based;
- a planned/incomplete integration.
