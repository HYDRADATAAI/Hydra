# Recruiter Proof Order

The public repo should answer these questions in this order.

## 1. What is HYDRA?

A market-intelligence data platform that turns fragmented inputs into governed, traceable intelligence.

## 2. What did you build?

Lead with:
- ingestion;
- canonicalization;
- schemas/contracts;
- lineage/provenance;
- validation;
- release gates;
- research-ready data products.

Do not lead with internal codenames or unfinished future features.

## 3. What proves it?

Surface:
1. canonicalization proof;
2. a representative contract/seam validator;
3. a fail-closed authority case;
4. a repair/rerun/freeze example;
5. a representative lineage or provenance artifact;
6. deterministic tests/checks.

## 4. How is it organized?

A recruiter should be able to move from README -> architecture -> proof -> representative code without opening giant internal archives.

## 5. What is intentionally not claimed?

Make real vs synthetic, research vs production, and implemented vs planned status explicit.
